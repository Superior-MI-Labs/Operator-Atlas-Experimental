05 / SYSTEM ARCHITECTURE

One engine. Several mathematical representations.

Operator Atlas is a modular research program. The visual graph is a client to a local API—not the owner of model state, data, training or numerical computation.

Operator contract

apply(x) → y
shape / dtype / kind
payload_bytes()
heatmap() / serialization

Dense, 8-bit quantized, low-rank, and low-rank plus sparse corrections use one contract.

Training

text → tokens → embedding
→ recurrent operators
→ logits → loss → gradients
→ qualified model artifact

PyTorch optimizes a small model. NumPy executes its exported parameters. Numerical parity is verified.

Equation search

observations → basis grammar
→ coefficient fitting → BIC
→ held-out error → result

Coefficient learning and equation-family discovery are different problems. The bounded 13-term grammar includes multiplicative interactions; saved equations can be composed with stage-wise domain refusal.

Evidence and inference

text → source hash → SQLite
prompt → current model artifact
→ traced activations → output

Evidence lookup is deliberately independent of parametric neural learning. New documents do not silently rewrite weights.

Research judgment: Operator Atlas is an experimental mathematical substrate and small language-generation demonstration, not a novel validated LLM architecture or a production assistant.
